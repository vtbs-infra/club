# 账号认证

当前源码以用户名、密码和已验证 B站 UID 建立账号。普通用户和主播没有邮箱字段，也不依赖
邮件服务。认证由 Fastify Cookie/Session、PostgreSQL 会话存储和 Node.js 异步 scrypt 组成。

本基线与旧认证模型不兼容；切换时必须在空数据库中初始化并重新注册账号，不导入旧账号
或密码摘要。已采用用户名与 UID 基线的数据库支持后续追加迁移，升级保留账号与业务数据。
旧认证模型的部署备份只能在其原版本独立恢复。

## 账号身份

| 字段     | 规则                                                         |
| -------- | ------------------------------------------------------------ |
| 内部 ID  | UUID，不作为登录名                                           |
| 用户名   | 3–30 位 ASCII 字母、数字或下划线；保存为小写；唯一且不可修改 |
| 显示名称 | 去除首尾空白后 1–80 个字符，可在账号页修改                   |
| B站 UID  | 普通用户和主播必须有已验证 UID；唯一且不可修改               |
| 密码     | 12–128 个字符；只保存带随机盐的 scrypt 摘要                  |
| 管理员   | 通过服务器 CLI 创建，UID 可以为空                            |

用户名登录忽略大小写。账号密码与 B站密码无关，平台不索取 B站凭据。成为主播只改变平台
角色并创建主播档案，档案通过账号 ID 和 UID 的复合外键引用已验证身份。

## 注册

1. 匿名浏览器在 `/register` 创建 `REGISTER` 挑战。
2. 服务设置 HttpOnly 浏览器 Cookie，分配已启用的验证直播间并返回一次性验证码。
3. 用户在指定直播间发送验证码，服务核对实际消息来源和 UID。
4. 原浏览器确认已验证 UID 后，填写用户名、显示名称及密码。
5. 服务在一个事务中消费证明、创建用户和密码凭据，随后用户使用新账号登录。

验证成功前不存在正式账号或密码凭据。一个 UID 只能创建一个账号；用户名冲突时可以在
证明有效期内换名重试。UID 已注册时应登录或找回现有账号。不存在后置绑定、解绑或身份转移。

## 找回账号与修改密码

`/recover` 先要求填写注册时的 UID，再创建 `RECOVER` 挑战。输入 UID 本身不证明归属，
也不返回账号是否存在。只有目标 UID 在指定直播间发出正确验证码，原浏览器才可看到
对应用户名并设置新密码。

找回挑战冻结目标账号 ID、UID 和凭据版本。提交时重新锁定并核对账号；密码更新、凭据
版本递增、全部会话撤销和证明消费在同一事务完成。其他旧找回证明随之失效。

已登录用户可在 `/account` 输入原密码修改密码，成功后也会退出全部会话。账号页只允许
修改显示名称，不允许修改用户名或 UID。

B站账号的控制权是自助找回的依据：失去该账号或无法发送验证消息时，无法自助找回 Club。
这条路线也依赖 B站验证直播间和消息接口可用；已有账号的用户名密码登录不依赖实时 B站请求。

## 证明与会话约束

挑战状态为 `PENDING → VERIFIED → CONSUMED`，另有 `EXPIRED` 和 `CANCELLED`。
等待验证与验证后提交分别有效 10 分钟；同一浏览器创建新挑战会取消其旧的未完成挑战。
服务只保存验证码和浏览器凭据的 HMAC 摘要，并检查：

- 发起浏览器、挑战用途、有效期和单次消费；
- 服务分配的启用房间、消息时间、实际发送 UID 与稳定事件 ID；
- 找回时的目标 UID、账号 ID 和凭据版本。

验证码只在创建响应中返回，后续查询不返回原始值。查询过期状态不触发外部验证。
后台按未完成挑战维持连接，重启后从 PostgreSQL 恢复需求；超过保留窗口的挑战会被清理。

全局最多同时保留 5,000 个未过期的 `PENDING` 或 `VERIFIED` 挑战。历史记录不占活动名额，
到期立即释放容量，不依赖后台先更新状态。取消本浏览器旧挑战、检查容量和创建新挑战在
同一数据库锁与事务中完成，因此满额时仍可重新验证，失败时保留旧挑战。历史记录在
`expires_at` 之后保留 24 小时，由后台清理；保留期不参与注册或找回的容量判断。

登录成功重新生成随机会话 ID，数据库保存其 SHA-256 摘要。会话固定有效 14 天，访问
不会续期。登出删除当前会话；改密、找回和管理员密码重置删除该账号的全部会话。
普通会话保存只能更新已有记录，延迟请求不能重新插入已撤销会话。登录和密码更新按账号
行锁串行化，登录提交前还会重新核对凭据版本。

生产 Cookie 为 HttpOnly、Secure、SameSite=Lax。写 API 验证与 `APP_URL` 一致的 Origin。
必须通过 HTTPS 使用生产认证；TLS 在反向代理终止时，应只允许可信代理访问应用并正确
设置 `TRUST_PROXY`。`AUTH_SECRET` 至少为 32 个随机字符，用于 Cookie 签名及证明摘要。

密码使用每次随机生成的 16 字节盐和 scrypt（N=32768、r=8、p=3），比较采用恒定时间比较。
未找到用户名时仍执行派生计算。登录和挑战有独立 IP 限流，写操作也按 IP 和用户限流；
密码派生限制同时执行的数量，不建立无限等待队列。注册、改密、找回和管理员凭据操作
写入事务审计，审计不含密码、密码摘要、会话 Cookie 或验证码。

## 管理员 CLI

完成数据库初始化后，在服务器运行：

```sh
npm run club -- admin:create --username admin --name Admin
npm run club -- admin:reset-password --username admin
```

CLI 在交互终端隐藏输入并确认密码。自动化时可临时传入 `CLUB_ADMIN_PASSWORD`，不能通过
命令行密码参数传入。创建命令拒绝已有用户名；重置命令只处理管理员，不能改动普通账号。
编译后的容器命令见[配置参考](configuration.md#管理员引导)。

## HTTP 接口

| 接口                              | 用途                    |
| --------------------------------- | ----------------------- |
| `GET /api/v1/auth/session`        | 当前会话，匿名返回 null |
| `POST /api/v1/auth/challenges`    | 创建注册或找回挑战      |
| `GET /api/v1/auth/challenges/:id` | 原浏览器读取挑战状态    |
| `POST /api/v1/auth/register`      | 消费注册证明并创建账号  |
| `POST /api/v1/auth/login`         | 用户名密码登录          |
| `POST /api/v1/auth/logout`        | 注销当前会话            |
| `POST /api/v1/auth/recover`       | 消费找回证明并重置密码  |
| `POST /api/v1/auth/password`      | 登录后凭原密码改密      |
| `PATCH /api/v1/me/profile`        | 修改显示名称            |

请求和响应以 `src/shared/contracts/auth.ts` 及运行实例的 `/openapi.json` 为准。
浏览器切换账号、登出或收到认证失效响应时，会替换私有查询缓存并重建页面，避免旧账号
数据出现在新会话中。

## 平台读取账号与验证通道

管理员在“B站集成”中扫码配置的是平台读取账号，与普通用户注册时证明的 UID 分开。
普通用户无需向 Club 提供 B站 Cookie 或密码。平台读取账号断开不会解除任何用户的 UID。

仅在读取账号有效且启用房间已完成 WebSocket 鉴权后创建挑战。通道暂不可用时明确返回
可重试错误，不提前发码等待建连。连接中断期间发送的消息不会通过历史接口补收，
页面恢复后应重发原验证码。已有 VERIFIED 证明仍可在原有效期内完成注册或找回。
B站故障不影响正常用户名/密码登录，也不阻止管理员重新扫码。
