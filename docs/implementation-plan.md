# Club 稳定版实施计划

> 状态：已执行
> 基线日期：2026-07-29

## 目标

Club 以一个 TypeScript 模块化单体完成 B站 UID 绑定、月度大航海名单冻结、礼物资格
生成、用户领取、主播发货和物流查询。当前版本面向单应用实例部署，使用 PostgreSQL
保存业务状态，以私有对象存储保存名单原始证据和礼物图片。

本计划的交付标准是：

- 资格、领取地址和订单状态由数据库不变量保护；
- 月末任务和后台 Runtime 的实际状态可观察、可恢复；
- 服务端、OpenAPI 与 Web 使用同一套领域契约；
- 普通用户、主播和平台管理员都能直接理解自己的主要工作流；
- 生产镜像只依赖编译产物和生产依赖；
- 空数据库安装和已有数据库升级都通过自动迁移。

## 产品不变量

### 账号与绑定

- 身份为 `USER`、`CREATOR` 或 `PLATFORM_ADMIN`，一个账号只有一个当前身份；
- 普通用户只能使用平台已启用的固定验证直播间完成 B站 UID 绑定；
- 验证消息在数据库事务处理成功后才标记为已消费；
- 已提交礼物单中的 UID、领取选项和收货地址不随账号后续变化。

### 月度名单

- 每个启用主播每个自然月都有一个名单任务；
- 计划开始时刻为主播时区当月最后一天 `23:59:00`；
- 第一次 Provider 请求前持久化 `capture_started_at`，并据此判断准点或迟到；
- 所有分页完成、一致性校验通过后才能定稿；
- 迟到结果必须由平台管理员确认；
- 定稿成员、接受的 Attempt 和原始证据不可修改；
- 同一任务同一时刻最多有一次有效抓取，最多执行三次。

### 礼物与领取

- 主播按实际需要创建月度礼物发布；
- 同一主播同一资格月份只有一个礼物发布；
- 礼物发布与名单定稿无论先后，都通过同一幂等匹配流程生成礼物单；
- 每个名单成员在一次发布中只有一张礼物单；
- 发布操作在一个事务内保存并发布当前页面的完整内容；
- 领取时使用当前账号的有效 UID 绑定；
- 提交后保存独立加密地址快照，地址簿变更不影响历史订单。

### 发货

- 一张礼物单最多对应一张运单；
- 创建运单后订单进入 `SHIPPED`；
- 物流 Provider 确认送达或主播明确完成后进入 `COMPLETED`；
- 状态变化写入历史记录并保留操作者审计。

## 技术结构

```text
src/
  server/
    infrastructure/
      db/schema/          # 按领域拆分的 Drizzle Schema
      runtime/            # Runtime 状态与重试
      storage/            # 本地/对象存储边界
    modules/
      binding/
      snapshots/
      gifts/
      fulfillment/
      announcements/
  shared/contracts/       # TypeBox API 契约
  web/
    api/                  # 按领域拆分的浏览器 Client
    components/
    pages/
    styles/               # token、基础、Shell、领域与响应式样式
```

主要工作流服务：

```text
snapshots/
  snapshot-service            任务准备、认领、采集与定稿
  snapshot-query-service      角色受限查询和证据校验

gifts/
  release-service             草稿和发布事务
  eligibility-service         名单与发布的资格匹配
  claim-service               到期和领取事务
  order-query-service         用户与主播订单视图
  fulfillment-service         处理、发货、完成和取消

fulfillment/
  tracking-refresh-service    Provider 刷新与订单推进
```

## 质量门

```powershell
pnpm install --frozen-lockfile
pnpm check
pnpm test
$env:TEST_DATABASE_URL = '<postgres-admin-url>'
pnpm test:integration
pnpm build
pnpm test:e2e
docker compose build app
```

数据库测试会从 `TEST_DATABASE_URL` 连接到 PostgreSQL 的管理数据库，为每个需要完整
Schema 的套件创建独立临时数据库，应用全部迁移，并在结束后删除。

## 发布验收

一次发布必须确认：

1. 管理员可以登录并看到真实系统状态；
2. 至少一个验证直播间可被启用并建立连接；
3. 用户可以生成验证码并绑定发送验证码的 B站 UID；
4. 启用主播会生成月末任务，准点和迟到路径符合定义；
5. 名单与礼物发布能够双向幂等匹配；
6. 用户可以使用默认或指定地址提交礼物领取；
7. 删除地址簿记录后，授权角色仍可读取订单冻结地址；
8. 主播可以为订单录入一张运单并展示用户可识别的物流信息；
9. Runtime 故障、未迁移数据库和待配置平台不会显示为运行正常；
10. 日志、测试 Fixture 和错误响应不包含密钥或真实隐私数据。
